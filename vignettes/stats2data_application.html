Overview

stats2data simulates raw datasets whose summary statistics match reported summary statistics (the targets). Each module defines an objective, the discrepancy between the summary statistics of a candidate dataset and the targets, and minimizes it with simulated annealing. A run stops once the best objective value falls below the convergence threshold thresh or once the iteration budget is spent. In this vignette, a run whose best objective value is below thresh is called converged.

Convergence is a statement about the optimization only, that is, the simulated summary statistics reproduce the targets to within thresh. Many different datasets share the same summary statistics, and a simulated dataset is one of them. The results below are therefore described in terms of the optimization objective values, target-vs-simulated differences, run-to-run variability.

The vignette works through four examples:

  1. the Descriptives module (optim_vec()), using summary statistics of a simulated dataset with continuous and integer variables;
  2. the ANOVA module (optim_aov()), using the reported cell means and F-statistics of Reynolds and Besner (2008);
  3. the MLR module (optim_mlr()), using the reported descriptives, correlations, and regression estimates of Bardwell et al. (2003, 2007);
  4. the parallel workflow (parallel_optim()), using the MLR example.

Across the examples, the following functions are demonstrated:

  • the optimization functions optim_vec(), optim_aov(), optim_mlr(), and parallel_optim(), and the refinement step hill_climb();
  • the GRIM check check_grim();
  • the inspection methods print(), summary(), get_stats(), get_rmse(), and coef();
  • the plotting functions plot_convergence(), plot_cooling(), plot_fit(), plot_stability(), and the plot() methods;
  • the Shiny interface run_app().

1. Descriptives module: simulated example

optim_vec() simulates one vector per variable that reproduces a target mean and SD within given bounds. To illustrate its use, the targets are computed from a small simulated dataset with two continuous variables and one integer-valued variable.

1.1 Encoding the targets

set.seed(2026)
N <- 150
example_data <- data.frame(
  x1 = rnorm(N, mean = 100, sd = 15),           # continuous, symmetric
  x2 = rgamma(N, shape = 2, scale = 3),         # continuous, right-skewed
  x3 = rbinom(N, size = 20, prob = 0.3)         # integer-valued
)

The targets are the means and SDs rounded to two decimals, as they would typically be reported. The bounds are the observed minimum and maximum, rounded outward:

target_mean <- round(sapply(example_data, mean), 2)
target_sd   <- round(sapply(example_data, sd), 2)
range       <- rbind(lower = floor(sapply(example_data, min)),
                     upper = ceiling(sapply(example_data, max)))
integer     <- c(FALSE, FALSE, TRUE)

target_mean
#>    x1    x2    x3 
#> 99.65  6.25  6.15
target_sd
#>    x1    x2    x3 
#> 15.36  4.15  2.26
range
#>        x1 x2 x3
#> lower  61  0  1
#> upper 140 23 13

range holds one column of lower and upper bounds per variable; a vector of length two applies the same bounds to all variables. integer marks which variables are integer-valued.

1.2 GRIM check

For integer-valued data, not every mean is attainable: the sum of N integers divided by N can only take values on a grid of width 1 / N. The GRIM test (Brown & Heathers, 2017) checks whether a reported mean, rounded to decimals, lies on that grid:

check_grim(n = N, target_mean = target_mean[["x3"]], decimals = 2)
#> $test
#> [1] TRUE
#> 
#> $grim_mean
#> [1] 6.15

For a mean that fails, grim_mean returns the nearest attainable mean (hypothetical values):

check_grim(n = 7, target_mean = 3.45, decimals = 2)
#> $test
#> [1] FALSE
#> 
#> $grim_mean
#> [1] 3.43

1.3 Running the optimizer

For continuous variables, optim_vec() starts from a vector whose mean lies within thresh of the target mean and anneals the values toward the target SD; the moves keep the mean fixed. For integer variables, it draws a distribution from SPRITE (Heathers et al., 2018) via rsprite2 whose mean and SD match the targets at the number of decimals given by sprite_prec. The objective of each variable is the absolute difference between its simulated and target SD.

Both statistics are given to two decimals, so sprite_prec = c(2, 2), and thresh = 0.005 is set to half a unit of the last decimal (both are the defaults). The remaining arguments are at their defaults (max_iter = 5e5, init_temp = 1e-3, cooling_rate = NULL, i.e. (max_iter - 10) / max_iter, max_starts = 3).

set.seed(2026)
result_vec <- optim_vec(
  N           = N,
  target_mean = target_mean,
  target_sd   = target_sd,
  range       = range,
  integer     = integer,
  sprite_prec = c(2, 2),
  thresh      = 0.005
)

1.5 Diagnostics

plot_convergence() shows the best objective value across iterations. For a stats2data_vec result, run selects the variable. log_y = TRUE uses a logarithmic y axis, and the shaded band marks the region below thresh.

plot_convergence(result_vec, run = 1, log_y = TRUE)

The trajectory of x1 has 323 iterations. Integer variables are drawn by SPRITE without annealing, so their trajectory consists of a single value.

plot_cooling() shows the temperature schedule implied by init_temp, cooling_rate, and max_iter:

1.6 Target vs. simulated statistics

plot_fit() plots the difference between simulated and target statistics. With standardised = FALSE, the differences are on the original scale; the shaded band marks +/- thresh. order = "fit" sorts the statistics by absolute difference.

2. ANOVA module: Reynolds and Besner (2008)

Reynolds and Besner (2008, Experiment 5) examined how contextual predictability affects response times in word and nonword naming; the study was among those replicated by the Open Science Collaboration (2015). To our knowledge, the raw data are not publicly available.

2.1 Reported summary statistics

The study reports a 2 x 2 within-subjects design (S = 16) with four cell means, indexed by stimulus type (Factor1) and switch condition (Factor2): 543, 536, 614, and 618 ms. It reports MSE = 3070 for the Factor1 effect, F(1, 15) = 30.5 (partial eta squared .670) for Factor1, and F < 1 for Factor2 (.002) and the interaction (.015).

S   <- 16
mse <- 3070
target_group_means <- c(543, 536, 614, 618)
eta2   <- c(0.002, 0.015)  # Factor2, Factor1:Factor2
df_err <- S - 1

The numerator mean squares implied by the cell means of the balanced 2 x 2 within-subjects design are:

m_cell  <- matrix(target_group_means, nrow = 2, byrow = TRUE)  # rows: Factor1, cols: Factor2
m_grand <- mean(m_cell)
ms_f1   <- S * 2 * sum((rowMeans(m_cell) - m_grand)^2)
ms_f2   <- S * 2 * sum((colMeans(m_cell) - m_grand)^2)
ms_int  <- S * sum((m_cell - outer(rowMeans(m_cell), colMeans(m_cell), "+") + m_grand)^2)
c(ms_f1 = ms_f1, ms_f2 = ms_f2, ms_int = ms_int)
#>  ms_f1  ms_f2 ms_int 
#>  93636     36    484

The reported Factor1 statistics are consistent with each other: the implied mean square divided by the reported MSE gives F = 30.5, and F / (F + df_error) gives the reported partial eta squared of .670.

stopifnot(round(ms_f1 / mse, 1) == 30.5)
stopifnot(round(30.5 / (30.5 + df_err), 3) == 0.670)

For the two effects reported as F < 1, the F-statistics are set from the reported partial eta squared via F = eta^2 * df_error / (1 - eta^2) (one numerator degree of freedom). The modules require bounds for the outcome, which the study does not report; the range of the reported cell means is extended by four times sqrt(MSE), the residual SD implied by the MSE, and rounded outward. The summary statistics are encoded in one list of optim_aov() arguments:

F_value_derived <- c(round(ms_f1 / mse, 1), round(eta2 * df_err / (1 - eta2), 3))

sumstats <- list(
  S                  = S,
  levels             = c(2, 2),
  factor_type        = c("within", "within"),
  formula            = "outcome ~ Factor1 * Factor2 + Error(ID / (Factor1 * Factor2))",
  integer            = FALSE,
  target_f_list      = list(
    effect  = c("Factor1", "Factor2", "Factor1:Factor2"),
    F_value = F_value_derived
  ),
  target_group_means = target_group_means,
  range              = c(floor(min(target_group_means) - 4 * sqrt(mse)),
                         ceiling(max(target_group_means) + 4 * sqrt(mse)))
)
sumstats$target_f_list$F_value
#> [1] 30.500  0.030  0.228
sumstats$range
#> [1] 314 840

target_group_means lists the cells with Factor1 varying slowest (11, 12, 21, 22). Between-subjects and mixed designs are specified through factor_type (and, for unequal group sizes, subgroup_sizes).

2.2 Simulating a dataset

optim_aov() is called with its default hyperparameters (max_iter = 3e4, thresh = 0.005, max_starts = 3, init_temp = 1e-3, cooling_rate = NULL, i.e. (max_iter - 10) / max_iter). The objective is the RMSE between the simulated and target F-statistics.

3. MLR module: Bardwell et al. (2003)

Bardwell et al. (2003) examined whether depressive symptoms or apnea severity better predict fatigue in N = 60 patients with obstructive sleep apnea. This example uses the statistics reported there:

  • means, SDs, and ranges from Table 1;
  • the regression of fatigue on both apnea indices and depressive symptoms (Step 2) from Table 2;
  • the correlations of the three predictors with fatigue from the Results section.

The same descriptives and coefficients are reprinted in Bardwell et al. (2007), with ranges rounded to integers. The variables are the respiratory disturbance index (RDI), the percentage of time with oxygen saturation below 90% (SaO2), the Center for Epidemiological Studies Depression Scale score (CESD), and the fatigue-inertia subscale of the Profile of Mood States (Fatigue). To our knowledge, the raw data are not publicly available.

3.1 Encoding the targets

N           <- 60
target_mean <- c(RDI = 48.8, SaO2 = 17.3, CESD = 12.6, Fatigue = 10.8)
target_sd   <- c(RDI = 27.1, SaO2 = 20.1, CESD = 11.3, Fatigue = 7.3)
range       <- rbind(lower = c(RDI =  15, SaO2 =  0, CESD =  0, Fatigue =  0),
                     upper = c(RDI = 111, SaO2 = 80.9, CESD = 49, Fatigue = 28))
integer     <- c(FALSE, FALSE, TRUE, TRUE)

RDI and SaO2 are treated as continuous, CESD and Fatigue as integer-valued sum scores. Both means pass the GRIM check:

vapply(c("CESD", "Fatigue"), function(v) {
  check_grim(n = N, target_mean = target_mean[[v]], decimals = 1)$test
}, logical(1))
#>    CESD Fatigue 
#>    TRUE    TRUE

target_cor holds the upper triangle of the correlation matrix of all variables in target_mean, in the order of target_mean. Unreported correlations are NA and excluded from the objective:

vars    <- names(target_mean)
cor_mat <- matrix(NA_real_, 4, 4, dimnames = list(vars, vars))
cor_mat["RDI",  "Fatigue"] <- 0.11
cor_mat["SaO2", "Fatigue"] <- 0.20
cor_mat["CESD", "Fatigue"] <- 0.68
target_cor <- cor_mat[upper.tri(cor_mat)]
target_cor
#> [1]   NA   NA   NA 0.11 0.20 0.68

target_reg and target_se follow the terms of reg_equation, intercept first. The intercept is not reported; it is derived from the means and slopes via b0 = mean(Fatigue) - sum(b * mean(X)), and its standard error is set to NA:

reg_equation <- "Fatigue ~ RDI + SaO2 + CESD"
b            <- c(RDI = 0.023, SaO2 = 0.008, CESD = 0.438)
b0           <- target_mean[["Fatigue"]] - sum(b * target_mean[names(b)])
target_reg   <- c("(Intercept)" = round(b0, 3), b)
target_se    <- c(NA, 0.034, 0.048, 0.066)
target_reg
#> (Intercept)         RDI        SaO2        CESD 
#>       4.020       0.023       0.008       0.438

The arguments are collected in one list, which is reused in Section 4:

args_mlr <- list(
  N            = N,
  target_mean  = target_mean,
  target_sd    = target_sd,
  range        = range,
  integer      = integer,
  sprite_prec  = c(1, 1),
  reg_equation = reg_equation,
  target_cor   = target_cor,
  target_reg   = target_reg,
  target_se    = target_se,
  thresh       = 0.005
)

3.2 Running the optimizer

optim_mlr() first calls optim_vec() to simulate the marginals and then optimizes the values of the predictors with simulated annealing, followed by hill climbing (hill_climbs). In the marginal step, thresh applies to the continuous variables; the integer variables are matched by SPRITE to the precision given by sprite_prec. The objective is weight * correlation error + (1 - weight) * regression error, where the regression error includes the standard errors when target_se is given.

The call uses thresh = 0.005, the default of optim_mlr(), which equals half a unit of the second decimal, the precision of the reported correlations. A stricter threshold would demand more precision than the reported statistics carry. The coefficients are reported to three decimals, but they depend on means and SDs rounded to one decimal. For example, the rounding of the SDs of Fatigue (7.3) and CESD (11.3) alone leaves the CESD slope (0.438) uncertain by about +/- 0.005.

All other arguments are sprite_prec = c(1, 1) (one reported decimal) and the defaults (weight = 0.5, max_iter = 1e5, max_starts = 3, hill_climbs = 1e4; init_temp = NULL is calibrated from the objective changes of random swaps, cooling_rate = NULL is (max_iter - 10) / max_iter).

set.seed(2026)
result_mlr <- do.call(optim_mlr, args_mlr)

3.5 Balancing the objective with weight

weight sets how much the correlation and the regression components contribute to the objective. Objective values obtained with different weights are on different scales and are not compared directly; the unweighted RMSEs of get_rmse() are. The optimization is repeated with weight = 0.05:

set.seed(2026)
result_mlr_w05 <- do.call(optim_mlr, modifyList(args_mlr, list(weight = 0.05)))
rbind(
  "weight = 0.5" = unlist(get_rmse(result_mlr)),
  "weight = 0.05" = unlist(get_rmse(result_mlr_w05))
)
#>                   rmse_cor    rmse_reg     rmse_se
#> weight = 0.5  0.0001227945 0.001257002 0.007754376
#> weight = 0.05 0.0045908802 0.001160531 0.005647967

The table shows how the RMSEs of the correlations, coefficients, and standard errors change with weight in this example. Which balance is preferable depends on which targets matter most for the intended use of the data. The remainder of this section continues with the weight = 0.5 result.

3.7 Refinement with hill_climbs

After the annealing, optim_mlr() refines the best candidate by hill climbing: it repeatedly swaps pairs of values within a predictor column and keeps a swap only if it lowers the objective. hill_climbs sets the number of hill-climbing iterations (default 1e4); hill_climbs = 0 skips the refinement. The optimization is repeated without refinement and with a longer refinement. With the same seed, the annealing is identical across the calls, so differences reflect the refinement only:

set.seed(2026)
result_mlr_hc0 <- do.call(optim_mlr, modifyList(args_mlr, list(hill_climbs = 0)))

set.seed(2026)
result_mlr_hc5e4 <- do.call(optim_mlr, modifyList(args_mlr, list(hill_climbs = 5e4)))
rbind(
  "hill_climbs = 0"   = c(best_objective = result_mlr_hc0$best_objective,
                          unlist(get_rmse(result_mlr_hc0))),
  "hill_climbs = 1e4" = c(best_objective = result_mlr$best_objective,
                          unlist(get_rmse(result_mlr))),
  "hill_climbs = 5e4" = c(best_objective = result_mlr_hc5e4$best_objective,
                          unlist(get_rmse(result_mlr_hc5e4)))
)
#>                   best_objective     rmse_cor    rmse_reg     rmse_se
#> hill_climbs = 0      0.003278107 0.0013256098 0.001369679 0.007831782
#> hill_climbs = 1e4    0.002643694 0.0001227945 0.001257002 0.007754376
#> hill_climbs = 5e4    0.002643691 0.0001227945 0.001256523 0.007754468

track_objective covers the annealing only, so the effect of the refinement is visible in best_objective and the RMSEs, not in plot_convergence().

4. Parallel workflow: Bardwell et al. (2003)

Each run of an optimizer is subject to randomness, and many datasets share the same summary statistics, so repeated runs return different datasets. parallel_optim() repeats the optimization with the same arguments and collects the runs; seed gives each run its own reproducible random-number stream.

To keep the build time of this vignette short, the MLR optimization of Section 3 is repeated 10 times with a reduced iteration budget and run sequentially (cores = 1). For applied use, the default budget and more runs are recommended.

result_par <- parallel_optim(
  FUN   = optim_mlr, # MLR module
  args  = args_mlr,  # reported summary statistics
  runs  = 10,        # number of optimization runs
  cores = 1,         # number of parallel workers
  seed  = 2026       # reproducible seed per run
)

With cores > 1, parallel_optim() sets up a future::multisession plan (Bengtsson, 2021) and restores any previous plan on exit. Because every run has its own random-number stream derived from seed, the results do not depend on cores:

result_par <- parallel_optim(FUN = optim_mlr, args = args_mlr,
                             runs = 10, cores = 2, seed = 2026)

4.4 Stopping at the first converged run

With stop_conv = TRUE, parallel_optim() stops launching runs once a run has converged, i.e. its best objective value is below thresh. The example repeats the MLR optimization of Section 3 with its full iteration budget:

result_first <- parallel_optim(
  FUN       = optim_mlr,
  args      = args_mlr,
  runs      = 10,
  cores     = 1,
  seed      = 2026,
  stop_conv = TRUE
)
result_first
#> stats2data parallel result
#>   Module: mlr 
#>   Runs:   1 of 10 (stopped early)
#>   Converged: TRUE (thresh = 0.005 )
#>   Best objective (across runs): 0.00262738 
#>   Mean objective (across runs): 0.00262738

1 of 10 requested runs were completed. With cores > 1, runs are dispatched in batches of cores, so a whole batch completes before the check.
